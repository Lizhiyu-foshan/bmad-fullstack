# Part 1: 新手快速配置 (Getting Started)

## 概述

本部分手把手指导你从零开始初始化一个使用 BMAD-Fullstack 的全栈项目，包含目录结构、配置和基础代码。

**预计时间**: 15-20分钟  
**技术栈**: FastAPI + React + TypeScript

---

## 第一步：创建项目目录结构

```bash
# 创建项目根目录
mkdir my-fullstack-app
cd my-fullstack-app

# 初始化 Git
git init

# 创建目录结构
mkdir -p backend/app/{schemas,models,routers,services}
mkdir -p backend/tests
mkdir -p frontend/src/{types,api,components,pages}
mkdir -p frontend/public
mkdir -p .bmad/{templates,logs,features}

# 创建基础文件
touch README.md
touch .gitignore
```

### 最终目录结构

```
my-fullstack-app/
├── backend/                 # FastAPI 后端
│   ├── app/
│   │   ├── __init__.py
│   │   ├── main.py         # FastAPI 入口
│   │   ├── schemas/        # Pydantic Schema
│   │   ├── models/         # SQLAlchemy 模型
│   │   ├── routers/        # API 路由
```

## 第二步：配置 BMAD-Fullstack

创建 `.bmad/project-charter.yaml`：

```yaml
project:
  name: "My Fullstack App"
  description: "用户管理系统"
  version: "1.0.0"
  type: "fullstack"

backend:
  framework: "fastapi"
  schema_path: "backend/app/schemas"
  main_file: "backend/app/main.py"
  port: 8000

frontend:
  framework: "react"
  type_path: "frontend/src/types"
  api_client_path: "frontend/src/api"
  port: 5173

contract:
  naming_convention: "camelCase"  # 前端使用 camelCase
  check_field_names: true
  check_field_types: true
  check_required: true
  type_strictness: "strict"

# 生成配置
generation:
  auto_generate_types: true
  output_file: "frontend/src/types/api.ts"
  backup_existing: true
```

## 第三步：初始化后端 (FastAPI)

```bash
cd backend

# 创建 requirements.txt
cat > requirements.txt << 'EOF'

pydantic[email]==2.5.0

python-multipart==0.0.6
pytest==7.4.0
httpx==0.26.0
EOF

# 安装依赖
pip install -r requirements.txt

cd ..
```

### 创建后端入口文件

`backend/app/main.py`：

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI(
    title="My Fullstack App",
    description="用户管理系统 API",
    version="1.0.0"
)

# CORS 配置
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

@app.get("/")
async def root():
    return {"message": "API is running"}
```

## 第四步：创建基础 Schema

`backend/app/schemas/__init__.py`：

```python
from .user import UserCreate, UserResponse

__all__ = ["UserCreate", "UserResponse"]
```

`backend/app/schemas/user.py`：

```python
from pydantic import BaseModel, EmailStr, Field
from typing import Optional
from datetime import datetime

class UserCreate(BaseModel):
    """用户创建请求"""
    username: str = Field(..., min_length=3, max_length=50)
    email: EmailStr
    password: str = Field(..., min_length=6)
    age: Optional[int] = Field(None, ge=0, le=150)

class UserResponse(BaseModel):
    """用户响应"""
    id: int
    username: str
    email: str
    is_active: bool = True
    created_at: datetime
```

## 第八步：创建启动脚本

`start-dev.sh`：

```bash
#!/bin/bash

GREEN='\033[0;32m'
BLUE='\033[0;34m'
NC='\033[0m'

echo -e "${BLUE}=== 启动开发环境 ===${NC}"

# 检查后端 Schema
echo -e "${BLUE}[1/4] 检查后端契约...${NC}"
bmad-fullstack check

if [ $? -ne 0 ]; then
  echo "❌ 后端契约检查失败，请先修复问题"
  exit 1
fi

# 生成前端类型
echo -e "${BLUE}[2/4] 生成前端类型...${NC}"
bmad-fullstack generate-ts \
  --input backend/app/schemas \
  --output frontend/src/types/api.ts \
  --naming camelCase

# 启动后端
echo -e "${BLUE}[3/4] 启动后端服务...${NC}"
cd backend && uvicorn app.main:app --reload --port 8000 &
BACKEND_PID=$!
cd ..

# 启动前端
echo -e "${BLUE}[4/4] 启动前端服务...${NC}"
cd frontend && npm run dev &
FRONTEND_PID=$!
cd ..

echo -e "${GREEN}✅ 开发环境已启动！${NC}"
echo "后端: http://localhost:8000"
echo "前端: http://localhost:5173"
echo "API 文档: http://localhost:8000/docs"

trap "kill $BACKEND_PID $FRONTEND_PID; exit" INT
wait
```

赋予执行权限：
```bash
chmod +x start-dev.sh
```

## 第九步：CI/CD 配置

`.github/workflows/contract-check.yml`：

```yaml
name: API Contract Check

on:
  push:
    branches: [main, develop]
    paths:
      - 'backend/app/schemas/**'
      - 'frontend/src/types/**'
  pull_request:
    branches: [main]

jobs:
  contract-check:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.11'
      
      - name: Install BMAD-Fullstack
        run: pip install bmad-fullstack
      
      - name: Check Backend Schemas
        run: bmad-fullstack check --backend backend/app/schemas
      
      - name: Generate TypeScript Types
        run: |
          bmad-fullstack generate-ts \
            --input backend/app/schemas \
            --output frontend/src/types/api.ts \
            --naming camelCase
      
      - name: Check Type Consistency
        run: |
          if [ -n "$(git status --porcelain frontend/src/types/api.ts)" ]; then
            echo "❌ 生成的类型文件有变更，请提交更新后的类型文件"
            exit 1
          fi
      
      - name: Set up Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '20'
      
      - name: Type Check Frontend
        run: |
          cd frontend
          npm ci
          npx tsc --noEmit
```

## 2. 契约配置文件详解

### 2.1 project-charter.yaml 完整配置

```yaml
# .bmad/project-charter.yaml
project:
  name: "用户管理系统"           # 项目名称
  description: "全栈用户管理"     # 项目描述
  type: "fullstack"             # 项目类型
  version: "1.0.0"              # 项目版本
  team: "platform-team"         # 负责团队

backend:
  framework: "fastapi"          # 框架: fastapi | django | flask
  language: "python"            # 语言
  schema_path: "backend/app/schemas"     # Pydantic模型路径
  main_file: "backend/app/main.py"       # 入口文件
  port: 8000                    # 服务端口
  cors_origins:                 # CORS配置
    - "http://localhost:3000"
    - "https://app.example.com"

frontend:
  framework: "react"            # 框架: react | vue | nextjs
  language: "typescript"        # 语言
  type_path: "frontend/src/types"        # 类型定义路径
  api_client_path: "frontend/src/api"    # API客户端路径
  port: 3000                    # 开发服务器端口

contract:
  check_field_names: true       # 检查字段名一致性
  check_field_types: true       # 检查类型一致性
  check_required: true          # 检查必填/可选一致性
  check_enums: true             # 检查枚举值一致性
  type_strictness: "strict"     # 严格程度: strict | loose
  naming_convention: "camelCase" # 命名规范: camelCase | snake_case | pascalCase
  
  # 忽略规则
  ignore:
    - "**/node_modules/**"
    - "**/__pycache__/**"
    - "backend/app/schemas/internal.py"  # 内部API不检查
  
  # 忽略字段
  ignore_fields:
    global:                     # 全局忽略
      - "created_at"
      - "updated_at"
      - "id"
    by_endpoint:                # 按端点忽略
      "/api/users":
        - "password"           # 用户端点忽略密码字段
      "/api/internal/**":
        - "*"                  # 内部API全部忽略

# 类型映射自定义
type_mapping:
  custom:
    - python: "Money"           # 自定义金额类型
      typescript: "Decimal"
    - python: "JSON"            # JSON字段
      typescript: "any"
    - python: "ObjectId"        # MongoDB ID
      typescript: "string"

# 报告配置
reporting:
  format: "html"                # 格式: console | html | json
  output: "reports/contract.html"
  verbose: true
  notify:
    slack: "${SLACK_WEBHOOK}"   # 失败时通知Slack
    email: "${TEAM_EMAIL}"

# 生成配置
generation:
  auto_generate_types: true
  output_file: "frontend/src/types/api.ts"
  backup_existing: true
  naming_strategy: "camelCase"
```

## 3. 类型映射配置

### 3.1 默认类型映射表

| Python | TypeScript | 说明 |
|--------|-----------|------|
| `str` | `string` | 字符串 |
| `int` | `number` | 整数 |
| `float` | `number` | 浮点数 |
| `bool` | `boolean` | 布尔值 |
| `List[T]` | `T[]` | 数组 |
| `Dict[K,V]` | `Record<K,V>` | 字典/对象 |
| `Optional[T]` | `T \| undefined` | 可选值 |
| `datetime` | `string` | ISO8601格式 |
| `UUID` | `string` | UUID字符串 |
| `EmailStr` | `string` | 邮箱格式 |
| `HttpUrl` | `string` | URL格式 |
| `Decimal` | `string` | 高精度小数 |
| `Enum` | 联合类型 | `'a' \| 'b' \| 'c'` |

### 3.2 自定义类型映射

```yaml
type_mapping:
  custom:
    # 基础自定义类型
    - python: "ObjectId"
      typescript: "string"
      
    - python: "IPAddress"
      typescript: "string"
      validator: "ip-regex"
    
    # 枚举类型
    - python: "StatusEnum"
      typescript: "'active' \| 'inactive' \| 'pending'"
      is_enum: true
    
    # 带验证器的类型
    - python: "PhoneNumber"
      typescript: "string"
      validator: "phone-regex"
      pattern: "^1[3-9]\\d{9}$"
```

## 4. 检查规则配置

### 4.1 检查级别

```yaml
contract:
  # 错误级别: error | warning | ignore
  rules:
    field_name_mismatch: "error"      # 字段名不一致 → 阻断
    type_mismatch: "error"             # 类型不匹配 → 阻断
    optional_mismatch: "warning"       # 可选性不一致 → 警告
    enum_mismatch: "error"             # 枚举值不一致 → 阻断
    missing_field: "error"             # 字段缺失 → 阻断
    extra_field: "warning"             # 额外字段 → 警告
    naming_violation: "error"          # 命名规范违规 → 阻断
    doc_missing: "warning"             # 缺少文档 → 警告
```

### 4.2 临时例外

```yaml
contract:
  # 临时忽略（附带原因和过期时间）
  temporary_ignores:
    - rule: "TYPE_MISMATCH"
      field: "legacy_id"
      reason: "旧系统兼容，计划v2.0移除"
      expires: "2026-06-01"
      approved_by: "tech-lead"
```

## 9. 故障排查

### 9.1 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 检查找不到Schema | 路径配置错误 | 检查 `schema_path` 和 `type_path` |
| 类型不匹配但应为匹配 | 自定义类型未映射 | 在 `type_mapping.custom` 中添加 |
| 内部API被检查 | 未配置ignore | 添加 `contract.ignore` 规则 |
| CI检查失败 | 环境配置不同 | 确保CI使用相同配置文件 |
| 命名不一致 | naming_convention配置错误 | 检查前后端命名规范配置 |

### 9.2 诊断命令

```bash
bmad-fullstack doctor                     # 全面诊断
bmad-fullstack config list --verbose      # 查看详细配置
bmad-fullstack check --debug              # 调试模式
bmad-fullstack check --dry-run            # 模拟运行
```
